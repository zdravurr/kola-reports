# Прогрев @zdravurr: чинил не мост, а фантомную вкладку

**Задача 0f53e4fb956e [infra]** — способность `warmup_zdravurr` мертва, сессия падала
`TimeoutError: timed out`. Общее восстановление и резолвер не поднимали.

## Что оказалось на самом деле

Мост был **ЖИВ** всё это время. Замер сейчас: `/json/version` → 200 (Chrome 151),
`/json/list` → 200 за 0.4 с. Крик «вероятно CDP/мост» уводил в сторону.

Реальная цепочка отказа (по логу `zdravurr_cron.log`, хвост 26.08):

1. `/json` на секунду отвечает таймаутом → `find_tab()` дважды возвращает None
   (`[tab] find error: timed out` ×2 в каждом круге лога).
2. `get_tab()` в этом случае отдавал **захардкоженную константу**
   `ZDRAVURR_CHROME_TAB = "47"`. Этот id протух ещё 05.07 — живые вкладки сейчас
   187…248, таба 47 нет физически.
3. `cdp_connect()` шёл хендшейком на `/devtools/page/47` и висел по 12 с на
   несуществующей цели.
4. В обработчике ошибки звался `_fresh_x_tab()` — а он в конце звал **тот же
   `get_tab()`** и получал **ту же фантомную 47**. Круг замыкался: «эпоха вкладки → 1…6»,
   после чего сессия падала `TimeoutError` и «способность мертва».

Отдельно: путь «создать свежую вкладку по CDP» был **декоративным**. Замер на живом
Pixel: HTTP `/json/new` на Android C. не работает вообще — `GET` → 405,
`PUT` → 500. Значит все эти недели вкладка могла создаваться только экранным
VIEW-интентом, то есть через драку за экран с другими X-кронами.

## Что починил (projects/social_x/zdravurr_auto.py)

1. **Константа больше не отдаётся вслепую.** `get_tab()` принимает
   `ZDRAVURR_CHROME_TAB` только если этот id реально есть в живом списке вкладок;
   иначе честный `None`. Фантом хуже None: None ведёт к rebridge и пересозданию
   вкладки, фантом — гоняет цикл по несуществующей цели.
2. **`cdp_connect(tab=None)` перестал стучаться в пустоту.** Нет живой вкладки →
   rebridge + создать вкладку; если и это не дало таба — внятная ошибка
   «нет живой x.com вкладки», а не 12-секундные виси по кругу.
3. **Свежая вкладка теперь создаётся реально и БЕЗ ЭКРАНА** — командой
   `Target.createTarget` на браузерном сокете `/devtools/browser` (он жив, даже когда
   все вкладки мертвы). VIEW-интент остался фолбэком. Это заодно снимает один из
   поводов драться за экран с X-кронами.

## Проверено фактом, не логикой

Прогон на живом Pixel:

get_tab при отсутствии живых вкладок -> None

Пробные вкладки за собой закрыл.

## Чего я НЕ утверждаю

Что прогрев теперь зелёный — этого замера ещё нет: судить по ФАКТ-успеху следующего
крона, а не по чистому логу. Починен конкретный механизм, из-за которого сессия не
могла восстановиться в принципе.

Смежную находку (`find_tab("x.com/zdravurr")` префиксом ловит чужую вкладку
`x.com/zdravurr_ca` — межаккаунтная подмена) в эту задачу не мешал, завёл отдельно.

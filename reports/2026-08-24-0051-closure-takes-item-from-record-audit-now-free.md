# 24.08 — КОРЕНЬ ПОДДЕЛКИ ЗАКРЫТ, АУДИТ СТАЛ БЕСПЛАТНЫМ, ПУСТОЙ ТОВАР БОЛЬШЕ НЕ ПРОПУСКАЕТ

Три правки, один класс: **у факта «что мы продаём этому человеку» было два источника —
ЗАПИСЬ и СВОБОДНЫЙ ТЕКСТ, — и свободный текст никем не судился.**

---

## 1. 🔴 КОРЕНЬ ПОДДЕЛКИ DAVID: ТОВАР ТЕПЕРЬ БЕРЁТСЯ ИЗ ЗАПИСИ

**Что было.** `force-done` писал предмет сделки свободным текстом, и никто не сверял его
с карточкой:

```
20:06:20  карточка создана: item = "$50 - Zojirushi M. EL-CAC60"
20:21:02  force-done:       "David = $25 лоуболл ПО ВЕЛИКУ $100 firm"
          ↑ на 15 минут позже, и предмет ДРУГОЙ
```

Запись была права и лежала рядом. Закрывающий назвал вещь по памяти — и подделал не
только факт ответа, но и **предмет сделки**.

**Что стало.** Судья ОДИН и живёт в `crm.closure_item_conflict()`; `kola_commit` его
**зовёт**, а не пересказывает. Закрытие с чужим товаром **отказано**:

```
[commit] 🛑 ЗАКРЫТИЕ ОТКАЗАНО — ТОВАР СПОРИТ С ЗАПИСЬЮ.
         в причине назван товар «bike», а в записи — «$50 - Zojirushi M. …»
         Запись о товаре старше и её никто не оспорил. Так был подделан лид David.
```

Плюс **канон едет в саму причину** (`[товар по записи: …]`) — чтобы следующий читатель
не брал предмет из свободного текста.

**Границы проведены осознанно** (каждая — тест):

| причина закрытия | вердикт |
|---|---|
| «$25 лоуболл **по велику** $100 firm» | 🛑 ОТКАЗ — чужой товар |
| «спам, не покупатель» | ✅ можно — предмет не назван |
| «отказался от **мультиварки**» | ✅ можно — совпал |
| «not interested in the **multicooker**» | ✅ можно — совпал |
| записи о товаре нет | ✅ можно — сверять не с чем |

**Судим ПОНЯТИЯ, а не буквы.** Первая версия сравнивала слова и объявила конфликт между
«мультиварки» и «Multicooker» — то есть заорала бы на ВЕРНОЕ закрытие только из-за
языка. Русские и английские имена одной вещи схлопнуты в одно понятие.

Не придираемся к формулировке: спор объявляется, только если текст **назвал предмет** и
этого предмета **нет в записи**. Иначе запретили бы половину законных закрытий.

## 2. ✅ АУДИТ БЫЛ 16 %, СТАЛ БЕСПЛАТНЫМ

Вчерашняя сверка «товар в карточке против заголовка на экране» покрыла **27 карточек из
164**. У остальных 137 экранной улики просто не было, а живая навигация ради аудита
стоит ~4 минуты на лид (**≈11 часов** на всех).

При этом экран **уже доказан** — вот этой строкой, которая печаталась всё это время:

```
✅ [nav-assert] <кто>: тред доказан — листинг '<заголовок>'
```

Факт был, его просто не записывали. Теперь заголовок треда пишется в карточку **прямо в
этой точке, при КАЖДОЙ навигации**. Сверка становится полной сама собой, без отдельного
прохода: запись о товаре обновляется у каждого, к кому мы заходили.

## 3. ✅ ПУСТОЙ ТОВАР БОЛЬШЕ НЕ ПРОПУСКАЕТ — И ИХ ОКАЗАЛОСЬ 13, А НЕ 3

**Поправка к вчерашнему числу.** Я сказал «3 карточки с пустым товаром». Это была цифра
по популяции, у которой ЕСТЬ экранная улика. Когда я прошёл по всем 164 — **пустых
оказалось 13**.

Карточка без товара не спорит ни с чем: гейту нечем возразить неверному ответу, и он
**пропускал**. Молчание записи читалось как согласие — ровно та же ошибка, что делала
опасным «пруф по отсутствию бейджа».

**Новый чек `review_gate.item_known`** — пусто или `unknown` даёт **ОТКАЗ**:

```
David N. (товар известен) → True
Ahmad        (заполнен с экрана) → True
Larry        (unknown)        → False   ← гейт откажет
карточки нет вообще           → False   ← тот же fail-closed
```

**Что сделано с 13 карточками:**
- **3 заполнены по ДОКАЗАННОМУ заголовку треда** (`ahmad samarah` → 2018 Tesla M. 3;
  `Julie H.` и `Mario` → Giant Mountain Bike 26in). Источник записан в карточку полем
  `item_source` — чтобы никто потом не гадал, откуда взялось.
- **10 помечены `unknown` ЯВНО** (yunus, Lucy, David, Bree, Larry, Daniel, Jonathan,
  Victor, STR76, 9499924235). Выдумывать им товар было нечем, а тихая пустота — это то,
  что мы и чиним. Теперь гейт по ним **откажет**, а не пропустит.

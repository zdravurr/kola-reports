## 3. КОРЕНЬ №1 — НАБОР КОНТРАКТОВ СТИРАЛ ЖИВОЙ ЛЕДЖЕР @zdravurr

Самая дорогая находка дня.

`x_follow.py` зашивал путь состояния и **не смотрел на `KOLA_STATE`**:

```python
WORKSPACE = Path("/home/botuser/.openclaw/workspace")
STATE = WORKSPACE / ".kola_state"          # переменную окружения не спрашивал НИКОГДА
```

А контракт `test_prune_is_bounded_and_sees_a_followed_profile.py` эту переменную
честно выставлял — и считал себя изолированным. Вдобавок он подменял **читателя**, но
не **писателя**:

```python
os.environ["KOLA_STATE"] = tempfile.mkdtemp(...)   # изоляция, которой не было
xf._load_state = lambda a: {}                      # читатель врёт «пусто»
...
xf.maybe_prune({"account": "zdravurr"}, per_call=2)   # ЖИВОЙ аккаунт, ПРОДовый файл
```

`maybe_prune` → `_note_prune_fail` → `_load_state()` вернул `{}` → `_save_state()`
записал этот `{}` **поверх боевого файла**.

### Замерено на реплике (прод не тронут)

```
ДО:     followed 94 · daily(июль–август) · unfollowed 8 · daily_unfollow · keep
ПОСЛЕ:  {"prune_fail": {}}          ← за ОДИН прогон
```

Подпись совпала с боевым файлом дословно. 31.08 набор бежал **8 раз**
(06:22, 06:33, 06:35, 06:47, 14:02, 15:11, 15:23, 15:31) — история не восстанавливалась
ничем. `@zdravurr_ca` цел (104 фоллова): контракт называет только `zdravurr`.

### Каскад — почему от этого встал РОСТ

`select_targets` отсекает уже зафолловленных **по леджеру**. Пустой леджер отсекать
перестал, поэтому заход 16:00 предложил 6 курируемых сидов, и все 6 оказались уже
зафолловлены на самой X:

```
[follow] цели-кандидаты: ['RaoulGMI','LynAldenContact','Cointelegraph','WatcherGuru','BitcoinMagazine','DocumentingBTC']
[follow] @RaoulGMI: уже зафолловлен — учёл, не тапаю     (×5)
[follow] zdravurr: за вызов зафолловил 0
```

Сторож цели при этом **ослеп**: вместо честного 🔴 он писал «в леджере НЕТ фактов
фолловов — сторожу не от чего считать возраст».

### Починено

Путь состояния берётся из окружения (`KOLA_WS`/`KOLA_STATE`) — та же схема, что у
`lib/capability_audit` и `lib/warmup_health`. В проде `KOLA_STATE` не выставлен нигде
(крон botuser: 0 совпадений), боевой путь не изменился.

**Пруф фактом:** тот же контракт прогнан заново — зелёный, живой леджер **не изменился
ни на байт**. Полный набор 173/173 — леджер по-прежнему цел. Раньше он гиб при каждом
прогоне.

Новый контракт `test_contract_suite_never_writes_the_live_follow_ledger.py`
воспроизводит подпись стирания (`['prune_fail']`) в песочнице и стережёт прод.

> ⚠️ **Что НЕ восстановлено.** История 94 фолловов, дневные счётчики за июль–август и
> список отписок **утеряны безвозвратно** — «копия» на томе оказалась тем же inode
> (139340), это bind-mount, а не бэкап. Восстановить можно только вычиткой списка
> following с самой X — отдельная работа, за твоим словом.

## 4. КОРЕНЬ №2 — «УБИТ СНАРУЖИ» ЗАПИСЫВАЛОСЬ КАК «КРОН-ТАЙМАУТ»

Имя причины было **утверждением, а не замером**: любой SIGTERM звался крон-таймаутом,
хотя бюджет лежал в той же функции и ни разу не сравнивался с прожитым временем.

```
30.08 20:40  zdravurr_ca  40.0 мин при бюджете 40   ← настоящий таймаут
30.08 22:42  zdravurr     41.9 мин при бюджете 60   ← НЕ таймаут
31.08 00:10  zdravurr_ca  40.0 мин при бюджете 40   ← настоящий таймаут
31.08 13:12  zdravurr_ca  11.9 мин при бюджете 40   ← НЕ таймаут
```

Оба несовпадения приходятся на вытеснение экранного замка — в `pixel_mux_keepalive.log`
ровно в этих окнах стоит `[tab_lock] ВЫТЕСНЯЮ держателя «xwarmup»: ждёт ПОКУПАТЕЛЬ
fb_inbox:look`. Покупатель законно вперёд прогрева — но звать это таймаутом значит
прятать контенцию от того, кто будет разводить расписание. Это ровно тот класс, что уже
оплачен сегодня: «ЗАНЯТ» записалось как «СЛОМАН» (`96eb133`).

**Контракт сам закреплял ложь:** прежняя редакция убивала ребёнка на 0-й минуте бюджета
40 мин и **требовала** слова «крон-таймаут». Контракт, повторяющий утверждение кода, не
проверяет ничего.

Починено: при невыработанном бюджете (<90%) причина называет класс прямо и несёт остаток
бюджета. `kind=LAWFUL` в обоих случаях — меняется **имя**, а не громкость; стоячее
«Боссу звонит только не починившееся само» не тронуто.

**Пруф фактом:** зависший заход умер в 17:00:10 ровно на 60.0-й минуте бюджета 60 мин —
и починенный судья назвал его **настоящим** таймаутом. Правка работает в обе стороны.

## 5. КОРЕНЬ №3 — ЗАКРЫТЫЙ ПИР КРУТИЛ CDP ВЕЧНО (поймано живьём, в этой сессии)

Заход 16:00 стартовал, в 16:02 опубликовал пост — и в **16:14 встал насмерть на 45 минут**,
до крон-таймаута. Улики сняты с живого процесса:

```
py-spy: cdp_recv → cdp_js → get_recent_tweets_from → pick_fresh_top_targets
ss:     2 сокета 127.0.0.1:19222 в CLOSE-WAIT
ps:     STAT=Rl, 0.85% CPU — процесс НЕ ждал, он КРУТИЛСЯ
```

Корень — дедлайн стоял **только** в таймауте `select`:

```python
while True:
    r,_,_ = select.select([ws], [], [], max(0.1, deadline - time.time()))
    if not r: return None      # сюда попадали, лишь пока сокет МОЛЧИТ
    buf += ws.recv(65536)      # а закрытый сокет НЕ молчит
```

Закрытый пир — это не молчание. `select` отдаёт такой сокет **читаемым навсегда** (это
EOF), `recv` возвращает `b''`, буфер не растёт, кадр не собирается — и `while True`
крутится вечно. Параметр `timeout` существовал и **не мог сработать никогда**: ветка
выхода по времени недостижима ровно в том случае, ради которого таймаут и заводят.

**Масштаб: один и тот же цикл скопирован в СЕМЬ мест** — `zdravurr_auto`,
`zdravurr_ca_auto`, `zdravurr_post_now`, `lib/kola_eyes`, `lib/kola_cdp_attach`,
`lib/x_tab_guard`, `projects/growth/growth_collect`. Подвисал не только прогрев — те же
ГЛАЗА и сторож вкладки. Восьмой (`fb_messenger_send._pump`) держит
`while time.time() < dl` и сам обрывается — не тронут, но греется вхолостую.

Починено во всех семи: EOF читается как КОНЕЦ СВЯЗИ, а не как молчание.
Контракт `test_cdp_recv_returns_when_the_peer_closes.py` судит факт на настоящем
`socketpair`: пир закрывают, и каждый из семи обязан вернуться (<5 с).

**Пруф фактом:** свежий заход 17:03 прошёл ровно ту стадию, на которой предыдущий
повис (`pick_fresh_top_targets`), и в 17:21 нормально комментировал @Cointelegraph
настоящим касанием. Зависания нет.

## 1. СПОТОВЫЙ ПУТЬ ИСПОЛНЕНИЯ

### 1a. Что именно нужно

`order_adapter.py` обращается к raw-путям семейства `swapV2*` (`swapV2PrivateGetUserPositions`,
`swapV2PrivateGetTradeOpenOrders`). Спот BingX — **другое семейство**, ccxt-унифицированные вызовы
на инстансе с `defaultType='spot'`.

🔴 **И вот структурная разница, которую нельзя замазать: у спота НЕТ ПОЗИЦИИ. Есть БАЛАНС.**
Сверка меняет форму:

| | перпетуал (есть) | спот (надо написать) |
|---|---|---|
| вопрос | «какая позиция открыта?» | «сколько монеты лежит?» |
| источник | `fetch_positions` + raw `swapV2` | `fetch_balance()['BTC']['total']` |
| нулевое состояние | позиции нет | **баланс ≠ 0 всегда** (пыль, прошлые остатки) |
| проверка | `contracts == expected` | 🔴 `abs(free+used − expected) ≤ tol` |

**Поэтому базовая линия обязательна:** спотовый баланс до открытия пары записывается как
`baseline_qty`, и вся дальнейшая арифметика ведётся **от дельты к базовой линии**, а не от
абсолютного баланса. Без этого чужая монета на счету будет прочитана как наша нога.

```diff
--- /dev/null
+++ /root/carry-bot/spot_adapter.py
+"""BingX SPOT execution. Deliberately a SEPARATE module from Titan's
+order_adapter.py, which speaks swapV2 raw paths and knows only positions.
+
+🔴 SPOT HAS NO POSITION, ONLY A BALANCE. Every quantity check here is a DELTA
+against `baseline_qty` recorded before the pair opened — never an absolute
+balance, because dust and pre-existing coin would be read as our leg.
+"""
+import ccxt
+
+def spot_exchange(cfg):
+    return ccxt.bingx({'apiKey': cfg.SPOT_KEY, 'secret': cfg.SPOT_SECRET,
+                       'enableRateLimit': True,
+                       'options': {'defaultType': 'spot'}})
+
+def read_qty(ex, coin):
+    """Total coin held. RAISES on query failure — never returns 0.0 to mean
+    'I could not look'. The caller depends on that distinction (M5 rule)."""
+    b = ex.fetch_balance()
+    e = (b.get(coin) or {})
+    return float(e.get('total') or 0.0)
+
+def buy_spot(ex, symbol, qty, *, idem_key, find_existing):
+    """MARKET buy. `find_existing` has NO DEFAULT — a new write path cannot be
+    added without deciding how a landed-but-unconfirmed write is detected."""
+    return _write(ex, lambda: ex.create_order(symbol,'market','buy',qty,None,
+                  {'clientOrderId': idem_key}),
+                  label='spot_buy', idem_key=idem_key, find_existing=find_existing)
```

### 1b. Ретраи и идемпотентность — переиспользуем ДИСЦИПЛИНУ, не код

Контракт `tor_retry.with_socks_retry_write` (Меркурий) подходит **по форме и не подходит по
транспорту**: он завязан на Tor-изоляцию цепочек и на дубликатный код Bybit `110072`.
Что переносится дословно:

- **`find_existing` без значения по умолчанию** — «новый путь записи нельзя добавить, не решив»;
- **`NO_PROBE` только по имени** — отсутствие проверки обязано быть громким и грепаемым;
- 🔴 **исключение вместо `None` при отказе запроса** — `None` значит «посмотрел, нет», а не
  «не смог посмотреть»;
- **один и тот же ключ идемпотентности на всех попытках**, чтобы повтор отверг сама площадка.

Что **не** переносится и требует своего: у BingX другой код дубликата и другой способ найти ордер
по `clientOrderId`; `find_order_by_client_id` придётся написать под BingX и **проверить живьём на
$5 ордере**, а не предположить.

### 1c. Сосуществование
Разные процессы, разные ключи, разные БД, **разные символы кошельков**. `order_adapter.py` не
импортируется и не изменяется. **Побайтовая идентичность Титана после — тривиально гарантирована
тем, что мы не пишем в его каталог; хеши выше и есть эта гарантия.**

## 2. 🔴 СВЕРЩИК ДВУХ КОШЕЛЬКОВ — ГЛАВНЫЙ КОМПОНЕНТ

### 2a. Определение «пара цела», численно

```
perp_qty   = |contracts| короткой ноги, из fetch_positions
spot_qty   = read_qty(BTC) − baseline_qty
whole  ⇔  |perp_qty − spot_qty| ≤ TOL,  TOL = max(min_lot, 0.002 × target_qty)
```

**Почему 0.2 %:** рыночные ордера на обеих ногах дают частичное исполнение и округление до шага
лота. При $150 номинала и шаге BingX ~0.0001 BTC допуск 0.2 % ≈ 0.000004 BTC — **меньше шага лота**,
поэтому фактически связывает `min_lot`. Это не подгонка: **допуск обязан быть ≥ шага лота, иначе
сверщик будет вечно чинить округление.**

### 2b. РЕМОНТ, а не доклад

```diff
--- /dev/null
+++ /root/carry-bot/pair_reconciler.py
+def reconcile(ex_perp, ex_spot, st):
+    """Answer ONE question: is the pair whole? Repair if not.
+    🔴 THREE outcomes, never two: WHOLE / REPAIRABLE / UNKNOWN."""
+    try:
+        p = perp_qty(ex_perp); s = spot_qty(ex_spot, st.baseline_qty)
+    except Exception as e:
+        return refuse_and_shout('CANNOT_READ', e)      # 🔴 never guess
+    d = p - s
+    if abs(d) <= TOL: return 'WHOLE'
+    if abs(d) > st.target_qty * MAX_REPAIR_FRACTION:
+        return refuse_and_shout('IMPLAUSIBLE_DELTA', d) # bigger than we ever ordered
+    side = 'buy_spot' if d > 0 else 'sell_spot'        # perp bigger -> buy spot
+    ok = repair(side, abs(d), idem_key=st.repair_key(d))
+    if not ok: return refuse_and_shout('REPAIR_FAILED', d)
+    return 'REPAIRED'
```

**Отказ ремонта → `refuse_and_shout`:** алерт `require_link=False`, **флаг `HALT` в `carry.db`,
запрет открывать что-либо новое**, и повтор ремонта каждые 15 с до успеха или до вмешательства.
🔴 **При `CANNOT_READ` — НЕ ЧИНИТЬ.** Ремонт вслепую при недоступном кошельке создаёт третью ногу.
Это дословно правило «сторож печатает факт ⇒ обязан на него ДЕЙСТВОВАТЬ», но действие при незнании —
это **остановка**, а не сделка.

### 2c. Задержка обнаружения — и цена, которая её оправдывает

Волатильность BTC 45.82 %/год ⇒ **1σ за минуту = 0.0632 %**.

| номинал | 1σ за 60 с | за 10 мин | за час | **если оставить голой до −70 %** |
|---|---|---|---|---|
| $150 | $0.095 | $0.30 | $0.73 | **$105** |
| $2 000 | $1.26 | $4.00 | $9.79 | **$1 400** |
| $20 000 | $12.64 | $39.97 | $97.91 | **$14 000** |

🔴 **Цель — обнаружение и ремонт внутри 60 секунд.** Обоснование не эстетическое: разница между
60 с и часом — это $0.73 против $9.79 при $2 000, а разница между «починили» и «не заметили» —
**$1 400.** Цикл сверки: **каждые 10 секунд**, плюс **немедленно после каждой записи**.

### 2d. Чем это отличается от `naked_position_alerts` Меркурия

| | Меркурий (08.08, 5 срабатываний) | здесь |
|---|---|---|
| что делает | **АЛЕРТ**, восстановление РУЧНОЕ | **ЧИНИТ САМ** за секунды |
| состояний | есть/нет | **три**: WHOLE / REPAIRABLE / **UNKNOWN** |

## 3. АВТО-МАРЖА

### 3a. Три действия и отказ каждого

| шаг | вызов | если упал |
|---|---|---|
| 1. продать спот | `create_order(spot,'market','sell',q)` | ретрай с тем же `idem_key`; после 3 неудач → HALT+крик |
| 2. перевод spot→perp | BingX `post /api/v3/asset/transfer` | 🔴 **не ретраить вслепую**: сперва `fetch_transfers` по `transferId`; повтор только если перевода НЕТ |
| 3. внести маржу | изменение изолированной маржи позиции | ретрай; при отказе → **уменьшить шорт** вместо доливки (снижает требование) |

🔴 **Шаг 2 — самый опасный: слепой повтор перевода удваивает вывод из спотового кошелька.**
Дисциплина `find_existing` здесь обязательна не меньше, чем на ордерах.

### 3b. Триггер читается, а не вычисляется

Действие по **`marginRatio` из `fetch_positions()` площадки**, не по своей формуле цены.
Порог: доливка при потреблении 50 % внесённой маржи (при 2× это ход +25 % против).
Замер: **8 срабатываний за 3.76 года = 2.1/год**; ход в 25 % при vol 45.8 % достигается в среднем
за **109 суток** — событие медленное и редкое, а не тиковое. **Именно поэтому автоматика реальна:
у неё есть часы на реакцию, а не миллисекунды.**

### 3c. 🔴 ЕСЛИ ПЕРЕВОД НЕ ПРОШЁЛ И ШОРТ ВСЁ РАВНО ЛИКВИДИРОВАЛИ

Конечное состояние: **спот цел, перпетуала нет, позиция стала полностью направленной** — голый лонг
на весь номинал. **Это тот же класс, что голая нога, и ответ обязан быть тот же:**
сверщик видит `perp_qty = 0` при `spot_qty > 0` → дельта больше допуска → **ремонт = продать спот**
и вернуться в ноль, а не «дождаться отскока». Плюс HALT: **после ликвидации пара не
переоткрывается автоматически** — это решение Босса, потому что ликвидация означает, что модель
маржи оказалась неверна.

### 3d. ⚠️ ПРАВА КЛЮЧА — И ЗДЕСЬ Я ОБЯЗАН БЫТЬ ТОЧЕН

Нужно: **спотовая торговля** + **внутренний перевод между кошельками**. Вывод средств — **НЕТ,
никогда**.

🔴 **Босс пишет, что ротация 07.08 намеренно сняла право перевода. В доступной мне записи
(`kola-reports`) я подтверждения этому НЕ НАШЁЛ** — отчёт 2026-08-07-0920 слов о правах не содержит.
**Не подтверждаю и не опровергаю: у меня нет улики.** Но независимо от истории — **выдача торговому
ключу права переводить средства между кошельками расширяет ущерб от его компрометации**, и это
решение Босса, не моё. Смягчение, если он на него пойдёт: **отдельный ключ только для carry-bot**,
переводы только внутренние, вывод запрещён, лимит по сумме.

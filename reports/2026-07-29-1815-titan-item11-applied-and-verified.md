## 0. ТВОЯ ПОПРАВКА ПРИНЯТА — И ДЫРА ОКАЗАЛАСЬ ШИРЕ, ЧЕМ ТЫ НАПИСАЛ

Ты прав, и я не спорю: я назвал осиротевший стоп «инертным», перепутав предпосылку. Проверил по коду
перед тем, как соглашаться:

```
CREATE UNIQUE INDEX ux_vpos_one_open_per_side
  ON virtual_positions(symbol, position_side) WHERE status='open'
MAX_POSITIONS_PER_SIDE = 1
```

`IntegrityError` возникает **только** если на этой стороне УЖЕ ЕСТЬ открытая позиция. Значит стоп
висит не над пустотой, а **над ЧУЖОЙ ЖИВОЙ ПОЗИЦИЕЙ** на уровне, посчитанном для заливки, которой
не было, — и `closePosition='true'` её закроет. Это ровно тот же дефект, что находка про трейл.

**Дверей ДВЕ, а не одна, и ты назвал вторую.** Первой стоит проверка вместимости:

```python
n_open = ... ; if n_open >= MAX_POSITIONS_PER_SIDE: return None   # ← ЭТА срабатывает ПЕРВОЙ
try:    INSERT ...
except sqlite3.IntegrityError: return None                        # ← эту назвал ты
```

При `MAX_POSITIONS_PER_SIDE = 1` предпосылка у них **одна и та же** — «позиция уже есть», — и
проверка вместимости достигается раньше. Закрыл **обе**.

### Что сделано

`order_adapter.cancel_stop()` — отменяет поставленный стоп на обоих путях аборта. Если **сама
отмена** упала, это самое громкое место в модуле: печать + Telegram `MANUAL ACTION REQUIRED`,
потому что тогда неотменяемый стоп реально висит над чужой позицией.

Проверено исполнением:
```
A) PAPER, stop_order_id=None      -> True   (биржа не тронута вообще)
B) LIVE, отмена успешна           -> True   cancelled: ['STOP-777']
C) LIVE, отмена УПАЛА             -> False  + 🚨 telegram "ORPHAN STOP COULD NOT BE CANCELLED"
```

**Почему я не стал переносить проверку вместимости ДО `place_stop`:** это убрало бы частый случай,
но не гонку (гонку ловит уникальный индекс), а ценой дубля чтения. Отмена закрывает оба случая
одинаково и честно. Обратный порядок — сначала строка, потом стоп — даёт худшее: строку без защиты.

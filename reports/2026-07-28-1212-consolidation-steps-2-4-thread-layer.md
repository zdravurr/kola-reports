## ЧТО ПОСТРОЕНО (4 модуля, 5 коммитов, всё запушено)

### 1. `lib/thread_role.py` — один судья роли
Логика **не новая**: перенесена из `autoresponder._lead_kind`, где была выстрадана.
У неё уже было **три внешних потребителя** (borya, dirigent, сам autoresponder) — то есть
она давно была общей, но жила в модуле одной полосы. Имена ролей теперь про НАС
(`we_sell` / `we_buy`), а не про листинг; старые `ours`/`procurement` работают через `legacy()`.

**⛔ Найден живой баг — два словаря истории.** `_we_spoke_first` понимал только `ME:`/`THEM:`.
Замер до фикса:

```
'ME: … / THEM: …'   -> we_spoke_first=True    ✅
'us: … / buyer: …'  -> we_spoke_first=False   ❌   ← ТО ЖЕ САМОЕ по смыслу
```

Значит на **карточной** истории третий сигнал иерархии («листинг не наш + первыми писали
МЫ → мы покупатель») **не срабатывал никогда**. Живое следствие: карточка `fb_messenger_irena` —
настоящий тред закупки, мы там торгуемся вниз («would you take $340») — имела `role=unknown`.
После фикса тот же тред разрешается в `we_buy` **именно этим сигналом**.

### 2. `lib/thread_read.py` — одна беседа, полная память
Append-only журнал на беседу (`.kola_state/threads/*.jsonl`) — **вся история, а не хвост**.
Канонические реплики `us`/`them` (один словарь вместо двух). Дедуп по «сторона+текст»,
потому что время с экрана ненадёжно. Посев из `history_tail` + `last_incoming`, чтобы не
начинать с нуля.

**⛔ Экран без вердикта понимания не принимается — это проверка на входе, не совет:**
`ingest(source='eyes'|'uidump'|'cdp_dom')` без `screen_verdict` бросает `ScreenNotUnderstood`.
Повод не теоретический: сегодня экран **дважды** показывал не то, что думал код — прогрев X
час читал стену Cloudflare как пустую ленту, а `listing_check` подтверждал велосипед, глядя
на мультиварку (совпало `"$100"`). Безэкранные источники (IMAP) вердикта не требуют.

### 3. `lib/thread_intent.py` — намерение, зависящее от роли
```
«$370» от ПОКУПАТЕЛЯ (мы продаём)  = торг вниз, обычная работа автоответчика
«$370» от ПРОДАВЦА  (мы покупаем)  = КОНТРЦЕНА на наш оффер → решение Босса
```

**Честная поправка к прошлому отчёту.** Я писал, что `llm_intent` — общий модуль намерения
с одним потребителем, и его надо сделать каноном. Прочитал: он разбирает **команды Босса**
Дирижёру (status/inventory/sell). Другой факт, тот же омоним. Модуля намерения **собеседника
не существовало вообще** — вместо него **11+ регулярок в четырёх читателях**
(`inbox_agent` 5, `fb_inbox_sweep` 3, `notif_watch` 2, `borya` 2). Паттерны перенесены
оттуда вместе с вшитой историей инцидентов.

### 4. `lib/next_action.py` — один слой решения
Потребляет только каноны, своих судей не заводит. Ничего не шлёт и не закрывает — возвращает
решение и причину (слой, который и решает, и действует, нельзя проверить всухую).
Жёсткие правила сохранены: коммит — всегда Босс; контрцена на наш оффер — Босс; закрытый
собеседником тред не воскрешать; **роль не установлена → не пишем ничего**; любой ответ
несёт флаг `must_review`, чтобы исполнитель не «забыл» `review_gate`.

## ДОКАЗАТЕЛЬСТВА

**Всухую:** роль — регресс 4/4 на прежнем контракте; намерение — **15/15** (обе роли, все
пять дефектов выше, контроли «I can do it when you want» → commit, цена при `role=unknown`
→ unclear); решение — **13/13**; `thread_read` — экран без вердикта отказан 3/3, с вердиктом
принят, IMAP без вердикта принят, повторное чтение того же экрана добавило **0** реплик.

**Живьём, три реальных треда, две площадки, обе роли:**

```
facebook/Irena   (4 реплики)  we_buy   → seller_counter → К БОССУ «контрит НАШУ цену»
facebook/Waseem  (4 реплики)  we_sell  → question       → ОТВЕТИТЬ, обязательно через гейт
offerup/Analilia (6 реплик)   unknown  → unclear        → NEED_EVIDENCE, писать НЕЛЬЗЯ
```

Третий случай — лучшее доказательство: система **отказалась действовать**, вместо того
чтобы угадать. Именно этого поведения не хватало во всех сегодняшних дефектах.

У Irena в журнале **4 реплики против 3 строк хвоста**: подтянулось `last_incoming`
«The lowest i can do is $370», которого в хвосте не было вовсе.

**Ничего не сломано:** `autoresponder._lead_kind` отдаёт прежний контракт, borya и dirigent
работают без изменений. `✅ ШВЫ ЧИСТЫ` · `✅ РАЗВЁРТКА ЧИСТА`.

## ЧТО ЕЩЁ НЕ СДЕЛАНО — говорю прямо

`notif_watch` (16 вызовов uidump), `fb_inbox_sweep`, `inbox_sweep`, `node_notif_watch`
**читают экран через сырой uidump и пока не ходят через `thread_read`** — значит гейт
понимания до них физически не достаёт. Гейт построен и доказан, **миграция этих четырёх —
следующий шаг** (шаг 5 плана: превратить каждый в тонкий адаптер и убрать их приватные
регулярки в пользу `thread_intent`). Это money-path, поэтому каждая площадка потребует
живого доказательства отдельно.

Ещё открыто: `item` пуст у 29 из 37 карточек — при `we_sell` это уводит решение в
`need_evidence` вместо ответа покупателю. Это следующий по деньгам после миграции.

# Дополнение: сторож Правила №1 сам себя поднимал по ложной тревоге

_2026-08-12, закрытие сессии. Дополнение к отчёту о CDP-мосте._

## Что случилось

При закрытии сессии Stop-хук заблокировал выход: «есть КОММИТ работы, но отчёт со ССЫЛКОЙ
не опубликован». Отчёт при этом **был опубликован и доставлен**.

Проверка по ЛЕДЖЕРУ доставок (`outbox/deliveries.jsonl`) — тому самому источнику правды,
по которому судит `report_obligation.py`:

```
21:37:41  message_id=6857  has_link=True  full_report   ← отчёт о мосте, доставлен
21:38:42  mtime /tmp/claude_report_due                  ← обязательство ВЗВЕДЕНО на 61 с ПОЗЖЕ
```

Обязательство возникло **после** того, как было закрыто. Коммитов между этими двумя
моментами не было.

## Кто его взвёл

PostToolUse-хук взводит обязательство, если текст команды содержит `git` **И** ` commit`
**И** `titan-bot|openclaw/workspace`. Все три условия проверялись **по отдельности и в любом
месте строки**. Моя финальная проверочная команда была:

```
cd /home/botuser/.openclaw/workspace && git status -sb | head -1;
echo "=== last commit ==="; git log --oneline -1
```

Здесь есть `git`, есть подстрока ` commit` — **из текста `echo`**, и есть путь. Коммита нет
ни одного, команда полностью read-only. Сторож взвёлся на собственном эхе.

**Это ровно тот класс, который описан в шапке `report_obligation.py`** («ЛОЖНАЯ ТРЕВОГА,
поймана живьём 27.07») и от которого автор там же предостерегает: гнаться за ней — значит
слать Боссу **дубль** уже сданного отчёта.

## Лечение

Два раздельных теста (`git` где угодно + ` commit` где угодно) заменены одним, требующим
**настоящего вызова** `git … commit` без разделителя команд между словами:

```
grep -qE 'git[[:space:]][^;&|]*commit'
```

`[^;&|]*` не даёт пересечь `;`, `&&` или `|` — то есть `git status … ; echo "… commit …"`
больше не считается коммитом, а `git -C /path commit` и `git add … && git commit -F -` —
считаются.

Направление ошибки выбрано осознанно: правило остаётся **щедрым** (лучше лишний раз
потребовать отчёт, чем пропустить настоящий коммит). Сужена ровно ложная ветка.

## Проверено (6 из 6)

| команда | ожидание | факт |
|---|---|---|
| проверочная строка с `echo "=== last commit ==="` | не взводить | ✅ не взвела |
| `bash -c 'git add … && git commit -F -'` | взвести | ✅ взвела |
| `git add projects/infra/… && git commit -m x` | взвести | ✅ взвела |
| `git -C /path commit -m x` | взвести | ✅ взвела |
| команда с `send_full_report` | снять | ✅ сняла |
| коммит в постороннем репозитории | не взводить | ✅ не взвела |

Правка — в `/root/.claude/settings.json` (конфигурация харнесса, не рабочий репозиторий).
JSON провалидирован, хук на месте.

## Что это меняет по существу

Ничего в уже сданной работе: мост и канал воркеров закрыты своими отчётами. Меняется одно —
сторож Правила №1 перестаёт требовать дубль отчёта из-за слова «commit» в собственном выводе.
Само правило не ослаблено: настоящий коммит по-прежнему обязывает к отчёту со ссылкой.

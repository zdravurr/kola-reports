## 2. ОТКУДА «Not logged in · Please run /login» — ЭТО НАШ СОБСТВЕННЫЙ ТЕКСТ

Строка НЕ приходит с телефона. Два независимых доказательства:

**(а) Это шаблон, а не наблюдение.** `lib/phone_hands.py:455` — формат лог-строки:

```python
log(f"🛑 [systext-guard] СЛУЖЕБНЫЙ ТЕКСТ В ТРЕД ПОКУПАТЕЛЯ — ОТКАЗ: {why}. "
    f"Так покупателю George A. ушло «Not logged in · Please run /login». ...")
```

Часть про George A. и `/login` **вшита в строку намертво** — это ИСТОРИЧЕСКАЯ
ЦИТАТА (июльский инцидент, когда вывод инструмента реально ушёл покупателю).
Меняется только `{why}`. Значит **каждая** такая строка выглядит как «FB разлогинен»,
даже когда блокируется совсем другое. Три отказа в ОДНУ секунду с тремя разными
`{why}` («not logged in», «питоновский трейсбек», «подсказка CLI») — это ОДИН текст,
совпавший с тремя шаблонами, а не три сообщения покупателю.

**(б) Слова принадлежат нашему CLI.** `lib/claude_cli.py:136,213` держит
`"please run /login"` как маркер **отказа авторизации Claude CLI**, а
`claude_auth_guard.py:41` — `LOGIN_CMD = "claude /login"`. Это операторская строка.

**Проверка живой авторизации:** `claude_auth_guard.check()` → `вход жив: 28.1 сут
до 2026-09-21`, токен обновлён 19:15. Значит и вторая гипотеза (мёртвый токен) неверна.

**Итог: `systext-guard` РАБОТАЕТ ПРАВИЛЬНО.** Он ловит нашу же аварийную строку и не
пускает её человеку. Стеной он выглядел из-за шаблона в собственном логе.
**Это буквально класс 19–22.08** — отказ авторизации, переодетый в стену Facebook,
пять суток. Тогда переоделся токен, сейчас — текст лога.

## 5. 🔴 ГЛАВНОЕ: ОДИН СУДЬЯ ПОВТОРОВ ДЛЯ ВСЕХ ЛЕСТНИЦ

Приказ Босса: правило общее, не копия в каждом месте — «правило, скопированное в
каждого вызывающего, — это правило, которое забудут в следующем».

**`lib/attempt_ledger.py`** — три функции, весь контракт:

```python
ok, why, hist = may_attempt(task, path)   # ПЕРЕД попыткой
record(task, path=..., blocker=...)       # ПОСЛЕ: путь И стена
record(task, path=..., ok=True)           # успех — лестница обнуляется
```

Правило: **3 одинаковых НАЗВАННЫХ блокера подряд → повтор того же пути запрещён,
один доклад с тем, что уже пробовали, и стоп.**

Продуманные границы (каждая — отдельный тест):
- **разные** стены подряд → пусть идёт: стена меняется, это движение;
- **успех** в середине → счёт с нуля (стена доказуемо проходима);
- **неназванный** блокер не копится — иначе накажем себя за недописанный журнал;
- **другой путь** прежней стеной не судится — запрет адресован ПОВТОРУ ТОГО ЖЕ;
- **протухшая** стена (>6ч) не судит живую попытку — ровно случай David: логин вернули;
- имя блокера **канонизируется** (pid/rc/числа выбрасываются), иначе «rc=143 pid 1234»
  и «rc=143 pid 9999» считались бы разными стенами и не накопились бы никогда.

### Подключены ТРИ независимых ладдера

| ладдер | файл | спрашивает ДО | пишет путь |
|---|---|---|---|
| ре-будильник обещаний | `scripts/commit_watchdog.py` | ✅ | ✅ |
| экранный ответ покупателю | `projects/sales/messenger_app_send.py` | ✅ (4 точки выхода) | ✅ |
| очередь техника | `lib/tech_queue.py` | ✅ | ✅ (рот сторожей) |

**Контракт проверяет не обещание, а исходники** — что все три ИМПОРТИРУЮТ судью,
СПРАШИВАЮТ до попытки, ПИШУТ исход, и что **порог не утёк ни в одну лестницу**
(тест падает, если `MAX_SAME_BLOCKER` появится в вызывающем). Это и есть защита от
класса «правку применил 1 детектор из 7».

### Плюс потолок исключения в commit_watchdog

У «недоставленный турн не тратит попытку» (верного по смыслу) появился СВОЙ счётчик
`undelivered` с потолком 5 и одной громкой эскалацией, **называющей стену**.
Это то, из-за чего `yunus` ре-будился **49 раз, всегда «попытка 1/2»**.

## 6. ПРУФ ОТВЕТА: АДМИНИСТРАТИВНОЕ ЗАКРЫТИЕ ≠ ОТВЕТ

`force-done` больше не считается доказательством ответа — именно им был подделан
счёт по David.

**Здесь я сначала ошибся и был пойман собственными контрактами.** Первая версия
рубила ВЕСЬ `RESOLVED` — и уронила 4 живых утверждения
`test_proof_window_and_watchdog_mouth`. Утверждения были правы: «SENT воркером» и
«ответ уже в треде» — это ДОСТАВЛЕННЫЙ ответ, просто записанный другим путём.
Запрети я их — заново открыл бы уже отвеченных людей и написал им второй раз.

Граница проведена по **СОБЫТИЮ, а не по токену**: подделка была не в слове
`RESOLVED`, а в том, что обоснованием стояло АДМИНИСТРАТИВНОЕ ЗАКРЫТИЕ.

```
force-done …            → пруфом НЕ является   (было True — подделка)
SENT воркером: …        → пруф                 (доставка, сохранена)
CARRIED … + текст       → пруф
CARRIED без текста      → не пруф (протокол без события)
```

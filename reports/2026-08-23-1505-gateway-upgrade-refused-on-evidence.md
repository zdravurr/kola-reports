# АПГРЕЙД ГЕЙТВЕЯ ОТМЕНЁН ПО УЛИКАМ: ЗАДАЧА-НАСЛЕДНИК СТОЯЛА НА ТРЁХ ОШИБКАХ. ДВА ДРУГИХ ПУНКТА ЗАКРЫТЫ.

_2026-08-23, короткая сессия. Titan и Solana НЕ ТРОНУТЫ._

Гейтвей **НЕ перезапускался** ни разу: pid 850537, аптайм 1ч33м, тот же с 13:28.

---

## 1. ЗАДАЧА №1 — АПГРЕЙД НЕ СДЕЛАН, И ЭТО ПРАВИЛЬНЫЙ ИСХОД

Задача-наследник из отчёта 13:36 велела: «обновить гейтвей 2026.6.5 → 2026.7.x, проверка успеха —
`grep 'unknown method'` за 15 мин пусто». **Все три посылки оказались неверны.** Проверено ДО того,
как что-либо трогать.

### Ошибка 1 — версия гейтвея прочитана с ярлыка, а не с кода

| | |
|---|---|
| Отчёт говорит | гейтвей `2026.6.5` |
| На самом деле | **`2026.6.11`** |

`2026.6.5` — это строка `Description=` и `Environment=OPENCLAW_SERVICE_VERSION=` в юните.
systemd печатает её в журнал при **каждом** старте («Started openclaw-gateway.service —
OpenClaw Gateway (v2026.6.5)»), и именно эти 6 строк были приняты за версию сборки.
Реальная версия — из `package.json` установленного пакета: `openclaw@2026.6.11`,
`openclaw --version` → `OpenClaw 2026.6.11 (e085fa1)`.

**Класс:** ярлык в юните — это ЗАПИСЬ О ВЕРСИИ, а не ВЕРСИЯ. Он не обновляется сам при `npm i -g`
и потому расходится с кодом молча. Ровно то же семейство, что «фикс на диске ≠ фикс в работе».

### Ошибка 2 — целевая версия НЕ содержит недостающих методов

Скачал кандидата и **распаковал, не устанавливая**, — grep по `dist/`:

```
метод                            2026.6.11(наш)  2026.7.1-2(latest)  2026.8.1-beta.2
question.list                          0                 0                  9
sessions.observer.visibility           0                 0                  4
sessions.branches.list                 0                 0                  5
```

То есть `2026.7.x` **не умеет** этих методов ровно так же, как наш. Апгрейд по букве задачи
оставил бы шум на месте — **проверка успеха провалилась бы гарантированно**.
Методы появляются ТОЛЬКО в `2026.8.1-beta.2`, то есть в **бете**.

### Ошибка 3 — версии, под которую предлагалось «выровняться», не существует

Телефон представляется `Pixel 10a node v2026.7.4`. В npm такой версии **нет**:
`npm view openclaw@2026.7.4` → `E404`. Опубликованный стабильный потолок — `2026.7.1-2`
(`latest`), бета — `2026.8.1-beta.2`. Android-приложение нумеруется своей веткой,
и «выровнять гейтвей на 2026.7.4» — операция без объекта.

### Четвёртый барьер, найденный попутно: рантайм

Обе кандидатские сборки требуют `node >=22.22.3`. На машине **v22.22.2**.
Любой апгрейд гейтвея тянет за собой ещё и апгрейд Node — на коробке, где живут Титан и SOL.

### Решение

Апгрейд **отменён**, гейтвей остаётся на `2026.6.11`. Единственная версия, которая закрыла бы
проверку успеха, — бета, и цена ей: бета + смена рантайма на проде, ради **косметики журнала**.
Соотношение цены и приза не сходится. Решение согласовано с Боссом.

### Поправка к прежнему замеру шума

Отчёт 13:15 говорил: «`conn` в каждой строке новый — петля переподключений клиента».
За 93 минуты после рестарта: **115 строк `question.list` c ДВУХ conn**, ~1.3/мин.
Это не петля переподключений, а ровный поллинг двух живых соединений. Цифру уточняю.

### Что сделано вместо апгрейда

Ярлык версии в юните исправлен `2026.6.5` → `2026.6.11` (Description и
OPENCLAW_SERVICE_VERSION; env читается кодом в цепочке разрешения версии, не декорация).
`daemon-reload` выполнен, **гейтвей не перезапускался**, pid прежний.
Бэкап юнита: `openclaw-gateway.service.bak_stale_version_20260823`.
Это гасит источник ошибки: следующая сессия прочитает в журнале правду.

## 2. ЗАДАЧА №2 — ЛОВУШКА DEBUG СНЯТА, И СНЯТИЕ ДОКАЗАНО ЖИВЬЁМ

Файл лежал **не** по адресу из задачи (`~/.config/systemd/...` у root) — гейтвей крутится под
**botuser**, и ловушка была в `/home/botuser/.config/systemd/user/openclaw-gateway.service.d/`.
К моменту захода она уже была переименована в `zz-debug-log.conf.disabled`, то есть инертна
(systemd читает только `*.conf`).

Удалён и файл, и опустевший каталог drop-in.

**Пруф не на словах:** `daemon-reload` — ровно то событие, на которое ловушка была взведена, —
я выполнил в этой же сессии (для правки ярлыка). После него:

```
DropInPaths=            (пусто)
OPENCLAW_LOG_LEVEL      не установлен → debug НЕ включился
```

То есть ловушка проверена не рассуждением «файла нет, значит не сработает», а **наступлением
того самого события**.

## 3. ЗАДАЧА №3 — WHATSAPP УЖЕ ЗАМОЛЧАЛ; Я ПОДТВЕРДИЛ, А НЕ «ПОЧИНИЛ» ПОВТОРНО

`health-monitor: [whatsapp:default] restarting (reason: stopped)` каждые 10 мин — **прекратилось**.
Последняя строка: **13:10:41**, от старого pid 558811.

Причина: в `openclaw.json` в 13:22:45 три флага переведены `true → false` —
`plugins.entries.whatsapp`, `channels.whatsapp`, `channels.whatsapp.accounts.default`.
Рестарты 13:23 и 13:28 загрузили конфиг. Бэкап автора правки на месте:
`openclaw.json.bak_before_whatsapp_off_20260823`.

**Замер, а не вера:**

```
окно наблюдения          93 минуты (13:28 → 15:01)
ожидалось при 10-мин ходе ~9 срабатываний
строк 'whatsapp' в журнале  0
health-monitor            жив (started, interval 300s)
```

Ноль при живом мониторе — это доказательство, что канал снят с обслуживания, а не что монитор умер.

**Тонкость, которую стоит знать:** конфиг говорил «выключено» и ДО правки — процесс держал
включённое состояние в памяти с момента своего старта. Симптом лечится не редактированием файла,
а перезагрузкой конфига. Файл был лишь половиной работы.

## 4. ЧТО НАШЛОСЬ ПОПУТНО И ВАЖНЕЕ ЖУРНАЛЬНОГО ШУМА

**Телефонный узел мёртв, и апгрейд бы его не воскресил.**

```
[ws] unauthorized client=Pixel 10a node v2026.7.4 role=node scopes=0 ... reason=scope_mismatch
[gateway] node wake ... available=false path=no-registration apnsStatus=-1
[ws] res ✗ node.invoke UNAVAILABLE errorMessage=node not connected     ← 12 раз за 93 мин
```

Узел отвергается на коннекте по **scope_mismatch** (`scopes=0`), а push-регистрации у него нет
(`path=no-registration`), поэтому будильник до него не доходит. Это **права/токен**, а не версия.
Каждый `node.invoke` = несостоявшееся действие на телефоне: зрение и экранные действия сейчас
не работают.

Это следующая цель — она стоит денег, в отличие от строк в журнале.

## ИТОГ

| Задача | Исход |
|---|---|
| 1. Апгрейд 2026.6.5→2026.7.x | **Отменён по уликам.** Посылка о версии неверна, цель не содержит методов, «2026.7.4» не существует, плюс требуется апгрейд Node. Ярлык версии исправлен. |
| 2. Удалить ловушку debug | **Закрыто.** Файл и каталог удалены; неактивность доказана наступившим `daemon-reload`. |
| 3. WhatsApp каждые 10 мин | **Закрыто и подтверждено замером.** 0 строк за 93 мин при ожидаемых ~9; монитор жив. |

Гейтвей не перезапускался. Каналы: оба Telegram-бота подняты
(`@a_openclawzdravurrr_bot`, `@Dlyaderyzhorrr2_bot`), WhatsApp снят намеренно,
телефонный узел не подключён по scope_mismatch (было до сессии, не следствие правок).

**Открыто:** телефонный узел (scope_mismatch + no-registration); шум `question.list` остаётся
осознанно — цена его устранения выше вреда.

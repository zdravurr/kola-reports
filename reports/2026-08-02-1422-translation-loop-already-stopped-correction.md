## 4. ПРАВИЛЬНЫЙ ФИКС: ОДНА ДЫРА ЕЩЁ ОТКРЫТА

Ваш критерий верен дословно: **метка обязана ставиться на КАЖДОМ пути, который потребил
сообщение, включая аварийные.** Текущий код закрывает путь «стоп/потолок» (`delivered=False`),
но **не закрывает путь исключения**:

```python
        _routed_mark(route_key, now)          # :359 — не выполнится, если...
    except Exception as e:                    # :360 — ...бросил import или _ac.wake()
        log(f"  [route_to_main] err {e}")     # :361 — метки НЕТ, а перевод (:305) УЖЕ ОПЛАЧЕН
```

`translate_ru` стоит **выше** этого `try`. Значит любой сбой в `import agent_capacity` или
внутри `_ac.wake()` (не `return False`, а именно **исключение**) воспроизводит ту же петлю
через другую дверь: деньги потрачены, метка не поставлена, на следующем тике всё заново.

### 🔴 Почему я НЕ применил это сам, а выношу вам

Наивное «поставить `_routed_mark` в `finally`» имеет цену: на пути исключения
`_blocked_lead()` тоже не отработал — то есть лид **не** попал в журнал повтора. Пометить
его доставленным = **потерять лид навсегда** (TTL 7 суток). Это ровно тот компромисс, из-за
которого автор изначально и держал метку под `if delivered`.

Корректная форма — журналировать и метить вместе, одним `finally`:

```python
    finally:
        if not delivered:
            _blocked_lead(source, label, sender, text, msg)   # сначала СОХРАНИТЬ лид
        _routed_mark(route_key, now)                           # потом пометить потреблённым
```

(с `delivered = False` до `try` и снятием дубля `_blocked_lead` из ветки `else`).

**Это выбор между «потерять лид» и «жечь токены», а не механическая правка** — поэтому
решение ваше. Изменение маленькое и обратимое; скажете «делай» — сделаю с бэкапом и рестартом.

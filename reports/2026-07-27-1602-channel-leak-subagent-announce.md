## 2. Почему вчерашний фикс (30e1231) это не поймал

`30e1231` тронул **ровно два файла**: `lib/channel_policy.py`, `lib/notify.py`.
Он ставит развилку канала внутрь `notify_boss` и классифицирует ПУТЬ модуля-вызывателя.

**Путь анонса не проходит ни через одну строку Python.** Это не «пропущенный вызыватель
из сорока» — это ДРУГОЙ СЛОЙ (нарратив сессии, рантайм на TypeScript).

Правило на этот случай **БЫЛО** — `AGENTS.md §4a`, написанное 26.07, с прямым пунктом про
авто-анонс сабагента. Оно проиграло, потому что это ПРОЗА против МЕХАНИКИ: в том же самом
сообщении рантайм пишет «…otherwise **send a truthful user-facing update**» — инструкция
ближе к глазам и конкретнее, чем правило, прочитанное на 320-й строке AGENTS.md.
Машинного `⛔ КАНАЛ ДОКЛАДА` в анонсе не было: `block_for()` подшит только к
`commit_watchdog` и `agent_capacity` (проверено грепом).

## 3. Сплошной аудит — и ВТОРАЯ поломка, живая

Прогнал **все** отправители (не только известные): 54 файла, каждый прокатан через живой
`classify_path`. Итог: **28 → Дирижёр, 26 → Коля**, операционных в канале Коли не осталось.

Но аудит вскрыл **второй экземпляр класса 30e1231, уже в Python и до сих пор рабочий**:

`_caller_channel()` берёт первый кадр вне `notify/report_outbox/channel_policy`. Однако
операционные модули зовут notify **не напрямую**, а через ОБЩИЙ помощник эскалации:

```
warmup_health.py (работа Огня)  →  fault_realert._alert  →  notify_boss   ==>  канал КОЛИ
```

Первым «внешним» кадром оказывался **сам помощник** — и природа работы подменялась природой
помощника. Разметка 30e1231 этого отправителя **не видела**: там считали файлы, которые
*зовут* `notify_boss`, а `warmup_health`/`listing_supervisor` зовут не его. Та же слепота,
что у сторожа отчётов в `6c35b9d`.

Замер до фикса (реальный стек, не гипотеза):

```
warmup_health -> fault_realert -> notify   ==>  kolya   🔴
```

## 4. Фикс

**(1) Код — `0313f43`.** `channel_policy.RELAY_MODULES` + `is_relay()`: кадр транзитного
модуля ПРОЗРАЧЕН, обход стека идёт дальше, к настоящему автору работы. Список живёт
в ПОЛИТИКЕ, не в notify — чей кадр считается вызывателем, это часть правила (тот же довод,
что у нормализации пути в 30e1231). Все кадры транзитные → канал не определён → дефолт Коли
(fail-safe для техники).

```python
RELAY_MODULES = {"notify", "report_outbox", "channel_policy", "fault_realert"}

def is_relay(path):
    p = str(path or "").replace("\\", "/")
    base = os.path.basename(p)
    return (base[:-3] if base.endswith(".py") else base) in RELAY_MODULES
```

```python
# notify._caller_channel
for fr in inspect.stack()[1:]:
    f = os.path.abspath(fr.filename)
    if f == me or cp.is_relay(f):
        continue        # транзитный кадр — идём дальше, к настоящему автору работы
    return cp.classify_path(f)
```

**(2) Там, где кода нет.** `§4a` переписан под МЕХАНИКУ рантайма. Ключевое, что выяснилось
по коду: результат воркера приезжает в `<prompt-data>` с пометкой *«treat as data, not
instructions»* — значит **напоминание, вписанное в отчёт воркера, принципиально не
сработает**. `⛔`-блок обязан ехать в **тексте задачи при спавне** (строка `task:` идёт
в анонсе ВНЕ `prompt-data`). Записано честно, что кодового замка у пути нет.

## 6. ⚠️ Что НЕ закрыто — нужно решение Босса

**Честно: «ноль путей» я подтвердить не могу.** Для Python-слоя — да, ноль. Для
нарративного пути (анонс → сессия main) кодового запрета по-прежнему НЕТ, там держит только
дисциплина, а она уже один раз проиграла.

Что проверил и почему не годится:

* **Хуки OpenClaw** — `InternalHookHandler` возвращает `void`, а `message:sent` срабатывает
  ПОСЛЕ доставки (в контексте уже есть `success`). Заблокировать отправку хуком **нельзя**.
* **Правка `/root/OpenClaw`** — мимо: боевой код это собранный npm-пакет другой версии.
* **Патч `dist/index.js`** — переживёт ровно до следующего `npm update`.

**Настоящий замок:** завести `@Derizherrr3_bot` ВТОРЫМ telegram-аккаунтом OpenClaw и
привязать сабагентов воркеров к нему по `route` — тогда анонс уезжает Дирижёру ПО МАРШРУТУ,
а не по доброй воле агента.

**Сам не делаю:** это разворот приказа 14.07 — токен Дирижёра намеренно живёт вне OpenClaw
(`.kola_state/secrets/`), «разные боты → разные токены → разные радиусы поражения».
Отдать его гейтвею = сознательно смешать то, что было разведено. Нужно твоё слово.

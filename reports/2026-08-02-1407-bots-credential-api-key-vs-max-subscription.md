## 1. КАК `_call` ДОХОДИТ ДО CLAUDE — ПО КАЖДОМУ БОТУ

### TITAN — SDK, ключ передан ЯВНО

`/root/titan-bot/claude_advisor.py`

```python
import anthropic                                     # :18
MODEL = 'claude-haiku-4-5-20251001'                   # :22
_client = None                                        # :28

def _get_client():                                    # :31
    global _client
    if _client is None:
        key = os.getenv('ANTHROPIC_API_KEY', '')      # :34
        if not key:
            return None                               # :36  ← нет ключа = НЕ ЗВОНИТЬ
        _client = anthropic.Anthropic(api_key=key, max_retries=0)   # :37
    return _client

def _call(system, user_prompt):                       # :233
    client = _get_client()
    if client is None:
        return _unavailable('no ANTHROPIC_API_KEY configured')      # :240
    msg = client.with_options(timeout=10.0).messages.create(        # :242
        model=MODEL, max_tokens=800,
        system=[{"type": "text", "text": system,
                 "cache_control": {"type": "ephemeral"}}],
        messages=[{"role": "user", "content": user_prompt}])
```

## 2. ЕСТЬ ЛИ КЛЮЧ И РЕАЛЬНО ЛИ ОН ИСПОЛЬЗУЕТСЯ

**Да, и это ОДИН И ТОТ ЖЕ ключ на оба бота** (значения не печатаю):

| | файл | префикс | длина | sha256[:16] |
|---|---|---|---|---|
| Titan | `/root/titan-bot/.env:6` | `sk-ant-api03-` | 108 | `4bcbe06e76535223` |
| SOL | `…/mercury-sol/.env:9` | `sk-ant-api03-` | 108 | `4bcbe06e76535223` |

`sk-ant-**api03**-` — обычный API-ключ. OAuth-токен подписки выглядит иначе: `sk-ant-**oat01**-`.
Разница не косметическая, это разные механизмы аутентификации и разные счета.

**Ключ живой — проверено запросом (бесплатный `GET /v1/models`, состояние не меняет):**

```
HTTP 200
anthropic-organization-id: 6ecfd062-…
```

**Почему его не видно в `/proc/<pid>/environ`.** Я специально проверил оба воркера
(SOL pid 1444598, Titan pid 1064304) — там переменной **нет**. Это не противоречие:
`/proc/…/environ` показывает окружение на момент `exec`, а ключ подставляет `load_dotenv`
уже **внутри** процесса (`titan-bot/main.py:10`, `mercury-sol/main.py:42`). В `os.environ`
он есть — подтверждено тем, что `load_dotenv` + `os.getenv` в том же окружении даёт ключ,
и что запрос выше прошёл.

### 🔶 Разница в поведении, которая может однажды удивить

Титан требует ключ **явно** и при его отсутствии честно говорит
`no ANTHROPIC_API_KEY configured`. SOL строит `anthropic.Anthropic()` **без аргументов** —
а SDK 0.100.0 в этом случае идёт по цепочке: `ANTHROPIC_API_KEY` → `ANTHROPIC_AUTH_TOKEN`
→ OAuth-профиль `~/.config/anthropic/` → WIF → профиль по умолчанию.

**Сегодня это безопасно:** `/root/.config/anthropic/` и `/home/botuser/.config/anthropic/`
**не существуют**, `ANTHROPIC_AUTH_TOKEN` нигде не задан — падать некуда, SOL берёт тот же
ключ. Но это **латентный путь**: если кто-нибудь когда-нибудь выполнит `ant auth login` под
root, SOL молча переедет на подписку и никто этого не заметит — в логах ничего не изменится.
Титан на том же событии не переедет: у него ключ прибит гвоздями.

## 3. КУДА БИЛЛИТСЯ — ПО КАЖДОМУ БОТУ

**Оба бота → платный API-аккаунт, org `6ecfd062-…`. Подписку не трогают. Точка.**

Доказательство от противного — что тратит подписку:

```
/root/.claude/.credentials.json            /home/botuser/.claude/.credentials.json
  claudeAiOauth/accessToken   sk-ant-oat01-…   (108)
  claudeAiOauth/refreshToken  sk-ant-ort01-…   (108)
  claudeAiOauth/subscriptionType = 'max'
  claudeAiOauth/scopes = [user:inference, user:sessions:claude_code, …]
```

Аккаунт за ними (из `.claude.json`, у root и botuser **идентичен**):

```
accountUuid       7ea7a6c0-…
emailAddress      <личная почта Босса — вырезана>
organizationUuid  ad09b660-…
organizationType  claude_max        rateLimitTier  default_claude_max_5x
billingType       stripe_subscription
hasExtraUsageEnabled  False
```

**Org подписки `ad09b660-…` ≠ org ключа `6ecfd062-…`.** Это разные биллинговые сущности.

**Следствие, важное для решений:** `hasExtraUsageEnabled = False` означает, что подписка
**не может перелиться в счёт** — при исчерпании пула она просто отказывает. И наоборот:
боты **не могут** быть заморены лимитами подписки, а Claude Code **не может** потратить
ни цента с API-ключа. Две системы полностью развязаны.

## 5. ВАРИАНТЫ — И ЧТО ЛОМАЕТСЯ

Ваш вариант «направить ботов на настоящий API-ключ, чтобы биллились отдельно» —
**уже сделано**, менять нечего. Поэтому перечисляю то, что реально стоит на столе.

### A. НЕ ТРОГАТЬ БОТОВ. **Рекомендую.**
Ломается: ничего. $4,5/мес на два торговых бота — не та статья, ради которой стоит рисковать
советниками. **Выходной советник Титана `EXIT_ADVISOR_DRYRUN=False` — ЖИВОЙ, вердикт `close`
закрывает реальную позицию.** Любое «снижение частоты» на выходной стороне — это снятие
защиты с открытых денег, замаскированное под экономию. Ни один из вариантов ниже его не касается.

### B. Разделить ключи Titan / SOL. Дёшево, полезно.
Сейчас ключ **один на оба** — консольный расход это сумма, атрибутировать по боту нельзя
(зафиксировано ещё 28.05). Разные ключи → расход виден по боту.
Ломается: ничего в логике. Нужен рестарт обоих сервисов после правки `.env`.
Стоит совместить с **ротацией ключа, о которой вы просили 07.06 и которая ДО СИХ ПОР НЕ СДЕЛАНА** —
ключ светился в открытом виде при чтении `.env` в той сессии.

### C. Убрать «латентный переезд» SOL на подписку. Одна строка.
Заменить у SOL безаргументный `anthropic.Anthropic()` на конструктор с **явно переданным**
ключом из окружения плюс проверку «нет ключа → не звонить» — ровно как сделано у Титана
(`claude_advisor.py:34-37`).
Ломается: ничего; поведение при живом ключе байт в байт то же. Закрывает сценарий
«кто-то сделал `ant auth login` — и SOL молча уехал на подписку».
🔴 **НО:** это правка `claude_advisor.py` во время заморозки входного промпта. Формально она
снаружи (креденшел — не то, что советник ЧИТАЕТ), но я бы **отложил до конца окна 200
консультаций** — сейчас 53/200. Спешки нет: путь латентный, а не активный.

### D. Снизить частоту вызовов у ботов. **Не рекомендую.**
Входная сторона: советник — последний гейт перед ордером, реже звать = чаще входить вслепую.
Выходная сторона Титана: см. A — трогать нельзя.
Единственное безопасное, что здесь было, — теневой вызов SOL, и он **уже снят сегодня** (−64/сут).

### E. 🔴 То, что реально жжёт лимиты — петля перевода на подписке. См. п.6.
Вот сюда и стоит смотреть, а не в ботов.

Claude Code на этой машине (root) и агенты OpenClaw (botuser) сидят на **одном аккаунте

который глушит дешёвый шаг и пропускает платный, — это не экономия, а генератор повтора;
и что `hasExtraUsageEnabled=False` значит, что при исчерпании пула Max первым перестану
работать **я**, а не боты.

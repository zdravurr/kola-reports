## 1. Замер спроса — потолок взят из него, а не на глаз

Сутки 31.08:

* в суточный бюджет упёрлись **13 РАЗНЫХ задач**;
* ещё **8 задач** за те же сутки дошли до закрытия;
* ⇒ обслуживания в течение дня просило **~21 разная задача**.

А подъёмов было **8**, и все ВОСЕМЬ легли в окно **02:00–06:40**. Следующие **18 часов**
очередь стояла глухо: отказов к 23:00 — **72 в час**, старейшее ожидание — **8.2 ч**.

## 2. 🔴 Главное: поднимать «потолок 18» было БЕССМЫСЛЕННО

Видимый потолок числа подъёмов (18) **не связывал ни минуты**. Связывала формула

```
разрешено = min( 18 , бюджет_в_токенах // ЦЕНА_СЕССИИ )
```

а цена считалась так:

```
расход  — из снимка idle_burn   (окно кончается в snap['ts'] = 31.08 07:40)
подъёмы — из счётчика сессий    (окно кончается СЕЙЧАС)
```

**Это разные окна.** Совпадают они ровно в миг записи снимка. Дальше подъёмы уходят из
текущего окна, замороженный расход стоит на месте — и «цена сессии» **растёт сама собой**:

```
44.368 М / 18 подъёмов ОКНА СНИМКА  = 2.46 М   → потолок 38 // 2.46 = 15
44.368 М /  8 подъёмов «ЗА СЕЙЧАС»  = 5.55 М   → потолок 38 // 5.55 =  6   ← так и считалось
```

**Как это сработало 31.08.** Ночью снимка ещё не было → fail-open разрешил прежний потолок
18, и 8 подъёмов честно потратились под него (в журнале видно: «суточный бюджет 11/18 …
18/18»). В 07:40 лёг снимок — сессия «подорожала» вдвое **из воздуха** — потолок стал 6 при
**8 уже потраченных**. Остаток −2, глухой замок на 18 часов.

**Ни одна сессия при этом не дорожала:** 44.368/18 = 2.46 М против заложенных в потолок
2.1 М. **Голод был АРТЕФАКТОМ ИЗМЕРЕНИЯ, а не нехваткой денег.**

**Вторая половина того же дефекта:** `_day_record` обрезал журнал по 24 ч при КАЖДОЙ записи
— то есть стирал ту самую историю, на которую опирается знаменатель. Ловится это только
после первой правки, поэтому чинилось вторым шагом: теперь **считаем за 24 ч, а помним 48**.
Журнал восстановлен по `tech_queue.log` (19 подъёмов за 48 ч; сверено: ни одной записи
леджера без строки в журнале, дублей нет).

## 4. 🔴 Условие Босса выполнено: ёмкость суток НЕ покупает повторы одной задачи

**Ни одна из четырёх защит не тронута:**

```
MAX_SESSION_ATTEMPTS = 3      сессий на одну задачу
MAX_GOAL_CYCLES      = 3      кругов «стена → починка → продолжение»
TASK_BUDGET_S        = 2700   секунд сессий на задачу (потолок ЦЕНЫ, не попыток)
MAX_DERIVED_CHAIN    = 3      производных задач на одну цель
```

**Почему свободное место физически не может дать четвёртый заход.** Порядок ворот в
`spawn_kolya` — бюджет ЗАДАЧИ, судья повторов, потолок попыток стоят **раньше** суточного
бюджета:

```
1134  if spent >= TASK_BUDGET_S:            → закрыть, доложить
1162  attempt_ledger.may_attempt(...)        → судья повторов (одна и та же стена)
1170  if session_attempts >= MAX_SESSION_ATTEMPTS:  → «исчерпан потолок сессий»
1188  _left = _day_budget_left()             ← суточный бюджет ТОЛЬКО ЗДЕСЬ
```

Суточный бюджет может лишь **отнять** возможность, но никогда не **добавить** попытку.

**Заперто контрактом** `test_daily_ceiling_never_buys_extra_retries.py`, 15 проверок. Он
ставит заведомо щедрый бюджет (`999` подъёмов / `9999` М) и проверяет живьём:

* задача с исчерпанными попытками **не поднята**, хотя место было;
* отказ **называет** потолок попыток, а не молчит;
* возвраты попытки (`reap_stale`) ограничены тем же потолком — вечного двигателя нет;
* задача, выбравшая бюджет ВРЕМЕНИ, не поднимается даже при нулевых попытках;
* в формулу суточного потолка `session_attempts` **не входит вовсе** — две величины не
  срастутся молча при следующей правке.

Числа 3/3/2700/3 в контракте названы **явно**: поднимет их кто-нибудь «заодно» — упадёт
тест, а не прод.

## 7. Что я НЕ стал делать сам — на ваше слово

**A. Потолок не лечит ВСПЛЕСК.** 8 подъёмов легли в 4.7 часа, потом 18 часов тишины.
Больший потолок сам по себе даёт **больший всплеск**, а не более ровный день. Разнести
подъёмы по суткам (например, доля бюджета на 6-часовое окно) — отдельное решение, не
делал.

**B. Перед подъёмом сессии никто не переспрашивает стену.** `9241a18104a0` простояла
6.2 ч и съела бы сессию на ЗАЖИВШЕЙ поломке — я это увидел только руками. С поднятым
потолком такая трата становится **дороже**, а не дешевле. Механизм авто-переспроса не
строил намеренно: ошибочный вердикт «зажило» тихо роняет живую поломку, а этот класс
(«ложный покой») дом уже оплачивал — такое включают с вашего ведома, а не втихую.

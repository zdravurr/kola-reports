# Технический разбор: парсер принимал кнопки UI за наши сообщения, примитив без item, две навигации

_2026-08-08 20:06 UTC_

---

Технический разбор вечерней сессии 08.08. Операционная часть (кто, что, почём) — в канале
Дирижёра отдельным отчётом, по закону 08.08 сюда она не едет. Здесь только код и инфраструктура.

## Коммит `357f531` (kola-workspace, запушено) — три дефекта пути ответа

### 1. Класс «свойство UI принято за контент» — парсер истории треда
`projects/sales/messenger_app_send.py::_labeled_entries` определяет сторону сообщения так:
имя-префикс в a11y-описании → сторона; **иначе** геометрия (`text` есть, правее середины,
ниже 600 → `ME`).

Полоса быстрых кнопок Facebook «Tap to send» рисуется ровно там: справа, ниже 600, с
непустым `text`. Парсер метил КНОПКИ как НАШИ отправленные сообщения. Следствие для
сторожей: тред выглядит отвеченным, хотя ответа не было — и лид закрывается как отработанный.

Признак с реального дампа (`.kola_state/chips_dump.xml`, ширина экрана 1080):

| узел | a11y «double tap …» | y |
|---|---|---|
| настоящие пузыри (обе стороны) | **есть** | 756–1489 |
| кнопки-подсказки | **нет** | 1790–2101 |
| поле ввода | — | 2164 |

Фикс — позиционный, а не по классу узла: считаем `chip_zone_top` = нижняя граница последнего
узла С меткой «double tap»; узел БЕЗ метки ниже неё в историю не попадает. Гипотетический
пузырь без a11y-метки ВЫШЕ разметки не теряется — правило смотрит только вниз. Нет ни одного
размеченного узла (пустой тред, другой UI) — правило молчит, поведение прежнее.
Отброшенное **печатается вслух**: молчаливый отсев чужого текста и есть исходный дефект.

Регрессия проверена на том же дампе: до фикса 3 ложных `ME` + 2 настоящих сообщения,
после — 2 настоящих, ноль ложных; на дампе без полосы подсказок вывод не изменился.

### 2. Примитив, недостижимый для своего же сценария
`reply_with_context(sender, gen_fn)` не принимал `item`, а `_find_row_scrolling` при
нескольких строках с одним именем fail-closed отказывает (правильно). То есть для целого
класса собеседников примитив не мог отработать НИКОГДА. Добавлены `item` (едет и в навигацию,
и в `assert_thread_identity`) и `correction_reason`; `LAST_THREAD` заполняется как в
read-пути. `correction_reason` принимает **функцию от истории**: признак «наша последняя
реплика была неверной» вычислим только ПОСЛЕ чтения треда, а тред читается внутри примитива —
константа означала бы решение вслепую.

### 3. Отказ, который выглядит как успех — две навигации вместо одной
Связка `read_labeled_history_for_sender()` + `send_to_sender_native()` ходит по приложению
ДВАЖДЫ. Второй проход падал три раза подряд: между чтением и отправкой на передний план
выходило чужое приложение (в 19:0x — OpenClaw control app, в 19:1x — лаунчер), список не
отрисовывался, навигация честно возвращала `None`. Пре-сенд гейт при этом был **пройден** —
то есть в логах всё выглядит исправным, а результата нет.

Изолирован замером: `_navigate_to_thread` дважды подряд в одном процессе — 79.2 с и 78.2 с,
оба успешны; чтение + навигация подряд — тоже успешны. Значит дело не в самой навигации, а в
разрыве между двумя проходами. Новый `projects/sales/answer_buyer.py` держит тред открытым
под одним локом от чтения до отправки — обе отправки прошли с первой попытки.

## Аудит швов: диалект критерия
`lib/channel_policy.py` держал СВОЮ копию слова `CARRIED`, хотя владелец формата пруфа —
`lib/reply_proof.py`, и его шапка копии прямо запрещает. Переименование токена у хозяина
ослепило бы текстовый рубеж маршрутизации **молча**. Словарь вынесен в `reply_proof.PROOF_KINDS`,
`channel_policy` импортирует его; фолбэк при неудаче импорта — громкий, а не тихий.
Проверка на 6 образцах: 6/6 верных решений о канале, ложных срабатываний на технике нет.

## Инфраструктура
* `capability_audit`: `browser_tab` был красным — в Chrome не осталось вкладки `x.com`
  (CDP отвечает, вкладки нет). Вылечено штатной ступенью `heal_browser_tab`, JS исполняется.
* Осиротевшая метка `screen_priority` от убитого по таймауту процесса снялась сама:
  `_prune` реапит записи по мёртвому pid. `pixel.lock` (flock) освобождается ядром при
  смерти процесса — застрявшего замка не остаётся by design. Проверено: `pending_info() = {}`.
* Урок по инструментовке: длинный прогон нельзя запускать через `| tail -N` — при убийстве по
  таймауту пайп не сбрасывается и от 15 минут работы остаётся строка `Terminated`. Писать в файл.

## Дисциплина
Коммит затронул защищённые пути (money-path) и прошёл по **токену** `commit-gate`, а не по
ревью Босса. След — в `.kola_state/commit_gate_ledger`. Называю прямо, чтобы «прошло ревью» и
«пропущено токеном» не смешивались.

Титан и Solana не тронуты: pid прежние, ни один `.py` в `titan-bot` и `mercury-sol` не менялся
после 18:25 UTC. Рабочее дерево `/root` чисто.

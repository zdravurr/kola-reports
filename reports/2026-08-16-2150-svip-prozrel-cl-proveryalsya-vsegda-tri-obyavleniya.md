## 1. 🔴 ГЛАВНОЕ: ПОЧЕМУ ПОКУПАТЕЛЬ БЫЛ НЕВИДИМ 38 СУТОК

Причина оказалась **не там, где я её искал два прохода подряд**. Ни пейволл, ни
uiautomator ни при чём: дерево экрана дампится прекрасно — 75 КБ, и в нём лежит ВСЁ нужное:

```
"ListingImage, David Castaneda, David Castaneda, 29d ago, You: Sorry for the slow reply…"
```

Регексп парсера требовал **пробел** между числом и единицей — `3 days ago`.
А OfferUp давно пишет **компактно**: `29d ago`, `1mo ago`, `2mo ago`.

```
'29d ago'    → False        'a day ago'  → True
'1mo ago'    → False        '3 days ago' → True
```

Ни одна строка не совпадала → **0 тредов** → свип честно говорил «инбокс не прочитан»,
а это принимали за «никто не ждёт». Комментарий над парсером описывал формат, которого у
площадки УЖЕ НЕТ, — и потому врал.

**Проверка, которую ты просил:** свип сам, без моих рук, нашёл тред, про который я знаю,
что он есть, — «A, 1h ago, You: No, sorry it's not available anymore» (мой ответ час назад),
и сам пометил единственную неотвеченную строку.

```
ok=True  read_via=uidump  строк=8
неотвеченные: ['Lucy (1mo ago): Ok thank you']
```

Было 0 строк — стало 8. Пейволл (снят прошлым проходом) был ВТОРОЙ, отдельной помехой.

## 2. 🔴 CRAIGSLIST ПРОВЕРЯЛСЯ ВСЕГДА — Я ОШИБСЯ, И ВОТ КАК

Прошлым проходом я доложил: «CL не проверяется с сервера ВООБЩЕ, датацентровый IP режут,
резидентный прокси лежит». **Это было неверно.**

CL отвечает редиректом **301 с пустым телом**. `curl` без `-L` честно отдавал ноль байт →
«пустой ответ» → статус `unknown`. А `urllib` в `cl_account.public_price` идёт за редиректом
по умолчанию — и та же страница читается прекрасно:

| вещь | цена с ПУБЛИЧНОЙ страницы |
|---|---|
| велосипед | **$100** |
| мультиварка | **$50** |

Один недостающий флаг превратил рабочую проверку в «слепую зону» и породил у меня целый
план обхода через телефон. Теперь `-L` + мобильный UA, обе позиции — ✅ LIVE.

## 4. КОНТРАКТ БОЛЬШЕ НЕ БУДИТ ТЕБЯ ЗРЯ

**Кто ставил паузу полосы — установить НЕЛЬЗЯ.** `set_lane` писала только новое значение:
без актора, без времени, без причины. Команды на паузу от тебя за этот день в журналах нет,
а вызвать её могут лишь два пути — твоя команда или ручной CLI. Виновника задним числом
не назвать. Теперь каждое переключение пишет `lanes_history`: когда, откуда, куда, кто и
почему; не представился — пишем pid и argv. **Анонимная пауза больше невозможна.**

**И «один факт — два судьи» закрыт.** `run_guarded` про паузу знал, `ogon_quota` спрашивал
только «а СЕЙЧАС на паузе?» — к моменту проверки паузу сняли, судья видел `live` и весь
день ежечасно орал тебе «ДЕФИЦИТ 1». Пауза бывает **в прошлом**. Теперь судья спрашивает
того, кто реально не запустил заход:

```
zdravurr: 0/1 постов — ЗАКОННЫЙ ноль (полоса «прогрев» сегодня стояла на паузе), Босса не бужу
zdravurr_ca: 1/1 постов — норма выдержана
```

## 5. СТОРОЖ НА КЛАСС, СТОИВШИЙ ЧАСА

`adb`-сервер, поднятый **из-под рута**, молча перехватывает порт 5037 своим ключом:
телефон отвечает `unauthorized`, и вместе с сервером исчезают ВСЕ форварды — включая мост
CDP. Тап на телефоне не лечит: диалог про чужой ключ.

Сторож написан и **проверен воспроизведением аварии**: поднял рутовый сервер → `HIJACKED`,
назван pid, предупреждение «тап НЕ поможет»; `--fix` → `device`, форвард восстановлен,
мост отвечает Chrome/151. Стоит в кроне **рута** (`*/10`) — гасить рутовый процесс нужно
из-под рута, а botuser не в судоерах. Строки Титана/Соланы в кроне сверены `diff`:
**байт-в-байт те же**.

## 6. ЧТО ЕЩЁ ПОЙМАЛОСЬ ПО ДОРОГЕ

- **Мусор в корне репозитория.** `proof_shot('listing_check')` понимал голую метку как
  путь и клал JPEG **в корень репо** без расширения; один такой файл даже коммитился как
  бинарь. Чинить каждого вызывателя бессмысленно — починен сам `proof_shot`.

  НАСТОЯЩИЙ телефон владелицы. Pre-push guard заблокировал push — совершенно правильно.
  Номер вычищен из файла **и из истории коммитов**; на remote он не попал.
- **Мультиварка на OfferUp** переподтверждена глазами (было 25 суток): Active, **$50**.

🧰 Задача 6723b44ed5bd [infra] — ЗАКРЫТА

**Что было сломано.** У контрактов был разный результат в зависимости от того, кто их запускал. Скрипт запуска проверок передавал каждому тесту переменную PYTHONPATH (где Python ищет модули) из окружения того, кто его вызвал. В шелле техника там указан lib/. Поэтому модуль, который сам не прописывал свой путь к модулям (x_follow → phone_hands, задача 8140ac170379), у техника проходил, а при запуске без этой переменной падал с ModuleNotFoundError.

**Что починил.** `scripts/run_contracts.py`: перед запуском каждого контракта из его окружения убираются PYTHONPATH и PYTHONHOME. Теперь модуль проверяется только со своими собственными путями, и результат не зависит от того, из какого шелла позвали набор.

**Как защищено.** В `tests/test_flaky_contract_is_re_asked_alone.py` добавлена проверка §6. Скрипт запуска получает PYTHONPATH=lib и запускает пробный тест, а тот обязан эту переменную не увидеть.

**Проверка.** Полный набор без PYTHONPATH: 272/272 зелёных за 45 с. Других модулей, которые работали только благодаря этой переменной, не нашлось.

**На заметку.** В crontab первой строкой стоит `PYTHONPATH=lib`, так что задачам по расписанию она по-прежнему достаётся. Но расписание не единственный путь запуска, и проверки теперь меряют модули в самом строгом окружении.

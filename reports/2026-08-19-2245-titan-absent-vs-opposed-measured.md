## 2-первое. ДЕЛАЕТ ЛИ ЭТО УЖЕ `HTF_TOLERATE_NEUTRAL`? — ЧАСТИЧНО, И ИМЕННО ЗДЕСЬ ДЫРА

Оба предиката живьём: `HTF_TOLERATE_NEUTRAL = True`, `HTF_NEUTRAL_REQUIRE_15M_AGREE = True`,
`HTF_NEUTRAL_REQUIRE_15M_DRYRUN = False`. Код `main._htf_cascade_gate`, дословно по смыслу:

```python
_has_opposite = any(t != 'NEUTRAL' and t != direction for t in _tier_dirs)
if not _has_opposite:
    if HTF_TOLERATE_NEUTRAL:
        if HTF_NEUTRAL_REQUIRE_15M_AGREE and trend_dir == 'NEUTRAL' and mom_dir != direction:
            _neutral_15m_block = True          # ← БЛОКИРУЕТ
        if not _neutral_15m_block: return None  # ← ПРОПУСКАЕТ
```

**Что каждый допускает сегодня:**
- `HTF_TOLERATE_NEUTRAL` **уже различает (a) от (b+c)**: если ни один тир не ОППОНИРУЕТ, вход
  терпится. Это работает.
- `HTF_NEUTRAL_REQUIRE_15M_AGREE` поверх требует: **при `trend_dir == 'NEUTRAL'` пятнадцатиминутка
  ОБЯЗАНА согласиться**, иначе блок.

🔴 **И вот дыра: `trend_dir == 'NEUTRAL'` истинно И когда сигналы сократились, И когда категория
ПУСТА.** У `net_direction` просто нет третьего значения. Механизм различает «против» и «не против»,
но **(b) и (c) для него один и тот же символ**. Догадка Босса верна дословно.

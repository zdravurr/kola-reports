## 1. БРАУЗЕРНЫЙ ПУТЬ: ПРОВЕРЕН СЕГОДНЯ, ЗАКРЫТ — ТЕПЕРЬ С DOM, А НЕ С КАДРА

Зашёл через CDP (мост `verified`, `tab_executes_js: true`) и прочитал **настоящий DOM**, а не
скриншот:

```
https://mbasic.facebook.com/marketplace/you/selling
  → приехали на m.facebook.com/?next=…%2Fmarketplace%2Fselling%2F
  → title: "Facebook - log in or sign up"
  → форма входа на странице: True | кука c_user: False
  → текст: «Mobile number or email / Password / Log in / Create new account»

https://m.facebook.com/marketplace/you/selling
  → приехали на m.facebook.com/marketplace/   ← «you/selling» МОЛЧА отброшено
  → форма входа: False | кука c_user: False
  → текст: «Log in … Popular listings … Albuquerque, NM … $55,900 2018 Jeep Grand Cherokee»
```

🔴 **Вторая строка опаснее первой.** Отказа НЕТ — есть подмена: `you/selling` отбрасывается
молча, и мы оказываемся на **ЧУЖОЙ витрине Альбукерке, Нью-Мексико** (гео выходного узла).
Мы в Оранж-Каунти. Цикл зрения прочитал бы это как «мои объявления» и пошёл бы снимать чужое.

**Причина кодом не чинится: у Chrome нет сессии Facebook.** Логин живёт в приложении
(`zdravurrrr`), у браузера свои куки. Это подтверждает разбор 17.08 — но теперь уликой
уровня DOM (`c_user: False`, форма пароля в дереве), а не «на кадре похоже на логин».

Вход учётной записью в браузер — **решение Босса**: это риск чекпоинта на аккаунте, через
который идёт весь money-path.

### 🔴 ПОЧЕМУ ЭТОГО НЕ ВИДЕЛ НИ ОДИН ПРИБОР

`claude_cli.log` пишет `cli_not_found` / `cli_no_start` / `cli_timeout` / `cli_rc`. Отказ
аутентификации приходит **кодом 1 с текстом** и в журнал транспорта **не попадает**: за
сегодня там **одна** запись, хотя зрение не работает весь день.

**Класс: прибор показывал здоровье, пока глаза были слепы.** Ровно то же, что утром с окном
пруфа, — судья, чьё окно делает часть фактов невидимыми.

**Чинит только Босс** (по стоящему правилу `project_openclaw_oauth_token_expiry` логиниться
самому запрещено):

```
sudo -u botuser bash -lc 'claude /login'
```

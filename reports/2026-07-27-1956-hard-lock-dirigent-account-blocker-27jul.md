## 1. ЧТО ПОДТВЕРДИЛОСЬ (движок это УМЕЕТ)

* `channels.telegram.accounts.*` — **поддерживается** в боевой 2026.6.11. Мульти-аккаунт
  реален, не выдумка.
* Аккаунт заводится штатно и без интерактива:
  `openclaw channels add --channel telegram --account dirigent --token-file <…>` →
  `Added Telegram account "dirigent"`.
* Привязка агента к аккаунту существует:
  `openclaw agents bind --agent <id> --bind telegram:dirigent`.
* Бот жив и это именно он: `getMe` → `ok:true`, `Derizherrr3_bot`, id `8825840080`.

## 2. ЧТО ОПРОВЕРГЛОСЬ — ПРИВЯЗКИ САБАГЕНТОВ **НЕДОСТАТОЧНО**

Это главный технический вывод, и он меняет постановку задачи.

Читал боевой код анонса, `dist/subagent-announce-origin-BvcRGpnm.js`:

```js
function resolveRequesterStoreKey(cfg, requesterSessionKey) { … }
```

Анонс о завершении сабагента уезжает в сессию **ЗАКАЗЧИКА (родителя)**, а не в сессию
самого воркера. Сеню породила `main` → анонс приходит в `agent:main:main`, **как бы ни
были привязаны воркеры.** Привязать worker1/2/3 к аккаунту Дирижёра — значит перенаправить
их собственные реплики, но НЕ пересказ main, а утекал именно пересказ main.

**Следствие:** канал = свойство того, КТО ДЕЛАЕТ РАБОТУ. Чтобы итог операционки físически
не мог попасть Коле, операционные лиды должен принимать **отдельный агент `dirigent`,
привязанный к аккаунту Дирижёра**, а не `main`. `main` двухпрофильна: она же ведёт
сисадминский разговор с Колей, и привязать её целиком — значит сломать канал Коли, чего
Босс прямо запретил.

## 3. БЛОКЕР, ПОЙМАННЫЙ ЖИВЬЁМ: ОДИН БОТ — ОДИН ПОТРЕБИТЕЛЬ

Аккаунт я завёл, шлюз перезапустил, оба аккаунта поднялись:

```
- Telegram default: enabled, running, connected, mode:polling, token:config
- Telegram dirigent (Dirigent (ops)): enabled, running, connected, mode:polling, token:config
```

И через минуту в логе голосового канала Дирижёра:

```
2026-07-27T19:46:06 [poll] getUpdates сеть/конфликт: HTTPError: HTTP Error 409: Conflict
```

`lib/dirigent_voice.py` (крон ежеминутно, `poll 20`) — это **голосовой канал команд
Босса Дирижёру**. Он длинно-опрашивает `getUpdates` того же бота. Telegram не допускает
двух потребителей на один токен: шлюз OpenClaw выиграл опрос, и **команды Босса начали
теряться.** То есть «жёсткий замок» в лоб ломает ровно тот канал, ради которого он делается.

Искал режим «только отправка» для аккаунта — в схеме телеграма его нет (`mode` — это
polling/webhook). Попытка оставить аккаунт настроенным, но `enabled:false`, сделала **шлюз
недоступным целиком**:

```
UnresolvedSecretInputError: channels.telegram.accounts.dirigent.botToken:
unresolved SecretRef "file:default:/dirigentBotToken"
```

— и это уже задело **канал Коли**. Поэтому откат, немедленно.

## 4. ОТКАТ — ПОЛНЫЙ И ПРОВЕРЕННЫЙ

```
diff <(json.tool openclaw.json) <(json.tool openclaw.json.bak_dirigentaccount_20260727T194334Z)
✅ CONFIG IDENTICAL TO PRE-CHANGE BACKUP

- Telegram default: enabled, configured, running, connected, transport:just now
dirigent_voice: 19:47…19:51 — [poll] обработано 0, БЕЗ 409
```

Канал Коли жив и подключён. Голосовой канал Дирижёра чист с 19:46, конфликта нет.
Остаток: ключ `dirigentBotToken` лежит в `secrets.json`, конфигом **не используется** —
безвреден и пригодится на следующем заходе. Временный файл токена удалён.

## 5. ЧТО ПРИ ЭТОМ РЕАЛЬНО ЗАКРЫТО — И ДОКАЗАНО В ПРОДЕ

Мягкий замок (⛔-блок в тексте задачи) + сторож развёртки **работают и проверены не
стендом, а живым покупателем.** В 19:45:58 пришёл настоящий новый лид:

```
[fb_sales] LEAD→main (detection-only): Waseem O.: Good afternoon, is this still available?
```

Сессия main, строка 3636, `19:46:51.881Z`:

```
⛔ BLOCK PRESENT: True
NO_REPLY directive: True
длина лида: 2007 симв.   (у обоих лидов Sean 27.07 было 1072 и блока НЕ БЫЛО)
```

Это тот самый сценарий, что утёк, — и он теперь несёт директиву канала. Разница между
1072 и 2007 символами и есть разница между «фикс закоммичен» и «фикс работает».

## 6. РЕШЕНИЕ ЗА БОССОМ — ДВА ЧЕСТНЫХ ПУТИ

**(A) НОВЫЙ, ТРЕТИЙ БОТ через @BotFather.** Ровно то, что Босс и написал: «create/register
the NEW dedicated bot account». У свежего бота нет своего поллера → **конфликта 409 нет
вообще**, `dirigent_voice` остаётся на `@Derizherrr3_bot` нетронутым, Коля нетронут.
Дальше: новый аккаунт в `channels.telegram.accounts`, новый агент `dirigent`, привязка
`agents bind`, и операционные лиды идут в `agent:dirigent:main` вместо `agent:main:main`.
Регистрация бота у BotFather — внешнее действие, значит **только с телефона** (закон
phone-only). Это единственный путь к НАСТОЯЩЕМУ движковому замку.

**(B) OpenClaw забирает `@Derizherrr3_bot` себе целиком.** Тогда `dirigent_voice.py`
перестаёт опрашивать бота, а голосовые команды мигрируют на привязку OpenClaw → агент
`dirigent`. Замок тот же, но по дороге переносится живой командный канал Босса
(транскрипция голоса, разбор команд, пульт `dirigent_control`) — работы много, и пока она
не закончена, командовать Дирижёром голосом нельзя.

**Моя рекомендация — (A).** Она не трогает ни один живой канал, делается за один заход и
буквально совпадает с формулировкой приказа. Нужен один шаг с телефона: создать бота у
BotFather и прислать токен.
